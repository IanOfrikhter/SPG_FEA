# AGENTS.md — правила работы AI-агентов в репозитории SPGFEA

Этот файл — источник правды о проекте для AI-ассистентов (ZCode и др.).
Перед началом работы прочитай его целиком. Если правило устарело — предложи правку этого файла, а не обходи его молча.

## 1. Что за проект

**SPGFEA** — учебный решатель метода конечных элементов (МКЭ) для геотехники, работающий целиком в браузере.

Ключевые свойства:

- **Только 2D** (плоская задача; осесимметричная — возможно позже). Никакого 3D.
- **Все вычисления на клиенте**: ядро МКЭ исполняется в браузере пользователя. Сервер (VPS в будущем) только раздаёт статику. Серверных расчётов нет и не должно появляться.
- **Интерфейс как у «взрослых» программ** геотехнического моделирования (стиль GEO5/SIO2D: лента инструментов, дерево задачи, расчёт по стадиям), чтобы студентам было легче перестроиться на коммерческие пакеты.
- **Учебная направленность**: код должен читаться студентами. Понятность важнее микрооптимизаций, кроме узких мест (сборка СЛАУ, решение, генерация сетки).
- **Верификация**: результаты сравниваются с реальными геотехническими программами, в первую очередь **SIO2D** (Fine / GEO5), а также с аналитическими решениями.

## 2. Технологический стек

> Раздел пополняется по мере принятия решений. «Предложено» ≠ «утверждено» — не считать фактом.

| Область | Решение | Статус |
|---|---|---|
| Язык фронтенда | TypeScript | предложено |
| Ядро МКЭ | TypeScript; при необходимости вынести в WASM (Rust/C++) | открыто |
| Отрисовка | Canvas 2D / WebGL | открыто |
| Сборка | Vite | предложено |

Не вводить тяжёлые зависимости (UI-фреймворки, 3D-движки, готовые FEM-библиотеки) без явного обсуждения.

## 3. Архитектурные правила

- Жёсткое разделение слоёв (структура папок утвердим в первой итерации):
  - `core/` — геометрия, сетка, МКЭ, материалы. Чистая логика, **без DOM и браузерных API** — должно запускаться и тестироваться в Node.
  - `gui/` — отрисовка, события, взаимодействие с пользователем.
  - `io/` — сохранение/загрузка проектов, импорт/экспорт.
- Внутренние единицы измерения: **м, кН, кПа, кН/м³**. Конвертация — только на границе ввода/вывода.
- Вещественные числа — `double` (JS `number`); плотные массивы — `Float64Array`.
- Нумерация для пользователя — с 1; во внутреннем коде индексы с 0 (узел `id` ≠ индекс массива — не путать).
- Ключевые алгоритмы (сборка матрицы жёсткости, интегрирование, законы пластичности) — с поясняющими комментариями с формулами/ссылками на литературу: это учебный проект.

## 4. Верификация и тесты

- Новая расчётная возможность = тестовая задача:
  1. Аналитическое решение, если существует (одномерное уплотнение, круговая выработка, подпорная стенка — активное/пассивное давление, и т.п.).
  2. Сравнение с SIO2D на той же задаче (по возможности тот же меш, те же параметры).
- Эталонные задачи хранятся в `benchmarks/` с README: описание, файл задания, ожидаемые значения (перемещения, напряжения, КЗ), допуск и фактическое расхождение.
- Расхождение с SIO2D в пределах ~1–2 % считать приемлемым, если оно объяснимо (разные законы пластичности, аппроксимации, итерационные допуски). Большие расхождения — расследовать, не маскировать подгонкой.
- Изменения в `core/` не коммитить, пока юнит-тесты не проходят.

## 5. Git-конвенции

- `main` — рабочая ветка. Фичи — короткоживущие ветки `feat/<имя>`, исправления — `fix/<имя>`.
- Сообщения коммитов — на английском, Conventional Commits: `feat:`, `fix:`, `docs:`, `bench:`, `refactor:`.
- Один коммит/PR — одна логическая единица работы.
- Секреты (ключи, токены) в репозиторий не попадают никогда. Большие бинарники и результаты расчётов — в `.gitignore`.
