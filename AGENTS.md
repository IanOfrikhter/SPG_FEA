# AGENTS.md — правила работы AI-агентов в репозитории SPGFEA

Этот файл — источник правды о проекте для AI-ассистентов (ZCode и др.).
Перед началом работы прочитай его целиком. Если правило устарело — предложи правку этого файла, а не обходи его молча.

## 1. Что за проект

**SPGFEA** — учебный решатель метода конечных элементов (МКЭ) для геотехники, работающий целиком в браузере.

Ключевые свойства:

- **Только 2D** (плоская задача; осесимметричная — возможно позже). Никакого 3D.
- **Все вычисления на клиенте**: ядро МКЭ исполняется в браузере пользователя. Сервер (VPS в будущем) только раздаёт статику. Серверных расчётов нет и не должно появляться.
- **Интерфейс как у «взрослых» программ** геотехнического моделирования (стиль SiO 2D/GEO5: лента инструментов, дерево задачи, расчёт по стадиям), чтобы студентам было легче перестроиться на коммерческие пакеты.
- **Студенты — только пользователи, никогда не разработчики**: они решают заданные преподавателем геотехнические задачи моделированием. В код они не лезут вообще никак и никогда. «Обучающий» здесь продукт, а не код: интерфейс имитирует профессиональный рабочий процесс (геометрия → сетка → расчёт по стадиям → результаты), чтобы студент после курса безболезненно пересел на коммерческие пакеты (GEO5/SIO2D/PLAXIS).
- **Аудитория кода — разработчик и AI-агенты.** Читаемость кода нужна для сопровождения и верификации, но приоритет производительности — обычный инженерный, без «учебных» скидок. Разрешено использовать готовые библиотеки там, где студенты ничего не теряют (генерация сетки, графики).
- **Верификация**: результаты сравниваются с реальными геотехническими программами, в первую очередь **SiO 2D** (ООО «НИП-Информатика», sio2d.ru; доступна только на рабочем ПК — см. §4), а также с аналитическими решениями.

## 3. Архитектурные правила

- Жёсткое разделение слоёв (структура папок утвердим в первой итерации):
  - `core/` — геометрия, сетка, МКЭ, материалы. Чистая логика, **без DOM и браузерных API** — должно запускаться и тестироваться в Node.
  - `gui/` — отрисовка, события, взаимодействие с пользователем.
  - `io/` — сохранение/загрузка проектов, импорт/экспорт.
- Внутренние единицы измерения: **м, кН, кПа, кН/м³**. Конвертация — только на границе ввода/вывода.
- Вещественные числа — `double` (JS `number`); плотные массивы — `Float64Array`.
- Нумерация для пользователя — с 1; во внутреннем коде индексы с 0 (узел `id` ≠ индекс массива — не путать).
- Ключевые алгоритмы (сборка матрицы жёсткости, интегрирование, законы пластичности) — с поясняющими комментариями и формулами/ссылками на литературу: это опора для верификации и будущих правок, а не учебный материал.

### Соглашение о сопровождении кода

Владелец проекта знает Python; TypeScript для него не родной язык. Поэтому:

- Каждый нетривиальный алгоритм AI сопровождает объяснением на русском — формулами и питон-подобной записью — до или вместе с реализацией.
- Владелец контролирует проект не чтением TS, а тестами и верификацией: ядро (`core/`) покрывается юнит-тестами с аналитически известными ответами, релизы — бенчмарками против SiO 2D (только на рабочем ПК, см. §4).
- Для особенно тонких мест (return mapping, разреженные решатели) допускается питон-«контрольная копия» алгоритма для сверки логики; это вспомогательный артефакт, в `src/` не попадает и в продукте не живёт.

## 4. Верификация и тесты

- Новая расчётная возможность = тестовая задача:
  1. Аналитическое решение, если существует (одномерное уплотнение, круговая выработка, подпорная стенка — активное/пассивное давление, и т.п.).
  2. Сравнение с SiO 2D на той же задаче (по возможности тот же меш, те же параметры).
- Эталонные задачи хранятся в `benchmarks/` с README: описание, файл задания, ожидаемые значения (перемещения, напряжения, КЗ), допуск и фактическое расхождение.
- Расхождение с SiO 2D в пределах ~1–2 % считать приемлемым, если оно объяснимо (разные законы пластичности, аппроксимации, итерационные допуски). Большие расхождения — расследовать, не маскировать подгонкой.
- Изменения в `core/` не коммитить, пока юнит-тесты не проходят.

### Окружение SiO 2D — только на рабочем ПК

⚠️ **SiO 2D установлен только на этом компьютере (рабочем) — лицензия университета.**
На домашнем ПК верификация невозможна: там меняется только интерфейс и код без обязательных
SiO 2D-прогонов. Расчётные изменения, требующие верификации, проверяются на рабочем ПК.

Параметры подключения (источник — проект-референс `C:\Users\ivo\Documents\Sio2D Auto`):

| Что | Значение |
|---|---|
| Программа | SiO 2D v2026.0.1 Educational, ООО «НИП-Информатика»; проекты `.sio2dedu` |
| Установка | `C:\Program Files\SiO 2D Educational\` (примеры: `<установка>\Examples\`) |
| Запуск в режиме API | `SiO2D.exe -api_server_name SIO2D-AUTO`; готовый скрипт: `Sio2D Auto\scripts\run_sio2d_api.bat`. Проект открыть/создать до подачи команд — без проекта команды вернут `NotAvailable` |
| Python-пакет | `sio2d_api` (wheel из `<установка>\Redistributable\`, на PyPI его нет); транспорт — Qt-локальный сокет (PyQt6) |
| Python-окружение | venv проекта «Sio2D Auto»: `C:\Users\ivo\Documents\Sio2D Auto\.venv\Scripts\python.exe` (Python 3.12) |
| Проверка связи | `...\.venv\Scripts\python.exe "C:\Users\ivo\Documents\Sio2D Auto\scripts\00_check_connection.py"` |
| Подключение из кода | `CSio2dApi("SIO2D-AUTO").execute_command("get Materials")` → `(Status, StatusMessage, Data-JSON)`; команды — те же, что в командной строке SiO 2D |
| База знаний по SiO 2D | `Sio2D Auto\docs\справочник_команд_sio2d_полный.md` (полный синтаксис команд), `Sio2D Auto\experience\EXPERIENCE.md` (журнал граблей и приёмов) |

Грабли API (выжимка из «Sio2D Auto»): команды строго последовательно, однопоточно;
`Calculate` асинхронный — поллить `get Stages` до `Status == Success` у всех стадий;
во время работы решателя ответы могут приходить битыми (`WrongResponse`) — это норма,
пережидать; не переключаться с вкладки «Стадии» до завершения расчёта; изменение полей
python-объектов не меняет проект — нужно ещё выполнить команду `set ...`.

Планируемый конвейер верификации SPGFEA ↔ SiO 2D: SPGFEA сохраняет задание бенчмарка (JSON) →
скрипт в `benchmarks/` строит ту же модель в SiO 2D через API, запускает расчёт, читает
результаты → сравнение величин с допусками, отчёт рядом с бенчмарком.

## 5. Git-конвенции

- `main` — рабочая ветка. Фичи — короткоживущие ветки `feat/<имя>`, исправления — `fix/<имя>`.
- Сообщения коммитов — на английском, Conventional Commits: `feat:`, `fix:`, `docs:`, `bench:`, `refactor:`.
- Один коммит/PR — одна логическая единица работы.
- Секреты (ключи, токены) в репозиторий не попадают никогда. Большие бинарники и результаты расчётов — в `.gitignore`.

## 6. Языки

- Идентификаторы и код — английский.
- Комментарии в коде и внутренняя документация — русский.
- UI и пользовательская документация (для студентов-пользователей) — русский; двуязычность UI — решение на потом.
